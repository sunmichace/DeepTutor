## 4. 已完成功能

### 4.1 Mock interview 主链路 ✅

CLI 子命令 `start / answer / profile / cancel`，状态机 `idle → questioning → answering → [followup]* → scoring → reviewing → completed`，session 持久化到 `data/interview/<user>/sessions/<sid>.json`。

### 4.2 Picker v1：画像驱动抽题 ✅

`deeptutor/agents/interview/picker.py` — 4 个核心函数 + `PickerHints` 数据类：

- `resolve_picker_hints`：从 profile + recent_sessions 派生 focus/avoid/difficulty
- `build_query_with_hints`：把焦点维度名 + 训练建议片段拼进 RAG query
- `filter_and_rerank`：基于 manifest 标签做软重排（focus +0.15 / diff +0.10 / avoid -0.20）
- 难度递进：最近 3 场均分 ≥70 → hard，≤50 → easy

coordinator 接入：`_select_question` 返回 `(question_text, picker_snapshot)`，snapshot 持久化到 `InterviewSession.picker_snapshot`。

### 4.3 训练建议结构化 ✅

`review_agent.py` 的 `TrainingSuggestionPayload`（Pydantic schema）+ JSON 块 + 三级 fallback：JSON → 文本 section → score-based。`clamp_review_length` 超长截断保留首/尾/JSON。

### 4.4 画像算法增强 ✅

`DynamicProfile` 新增字段：
- `resolved_dimensions`：已回暖的旧弱项
- `training_suggestion_history[*].status`：active / expired
- `_repeated_and_resolved_dimensions`：按时间序识别弱项是否回暖

### 4.5 Manifest 标签底座 ✅

### 6.3 picker V2 设计 ⚠️ 阻塞于真实数据积累

V1 已验证 `active_suggestion` 闭环。仍需 ≥3-5 场真实用户数据才能验证：
- `focus_dimensions` 派生（需 ≥2 场同维度低分）
- `dimension_trends` improving / declining（需 ≥2 场同维度评分）
- `avoid_question_types` 软降权效果（需 `resolved_dimensions` 非空）
- 难度递进 medium→hard / medium→easy（需 ≥3 场总分）

这些都不是"代码缺失"，是"数据不够"——必须等真实用户使用积累，或者构造一批合成 session 文件做验收。

### 6.4 已知 LLM 偶发问题

- 没有自动检测兜底——如果 followup 文本包含"根据考生的回答生成一个追问"等明显复读特征应识别为无效并跳过追问
