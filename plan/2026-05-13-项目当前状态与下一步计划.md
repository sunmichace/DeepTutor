## 3. 本阶段的核心问题

### P0 工作区脏且范围越界

- 67 条未提交变更，`scripts/ingest_interview_data.py` 一个文件就重写 ±693 行，继续叠加会让回滚颗粒度彻底崩溃。
- `deeptutor/api/routers/plugins_api.py` 与 `web/app/(workspace)/playground/page.tsx` 与"放弃前端/产品 API"声明冲突，需要尽快做取舍。

### P0 标签尚未经人工抽检

- 规则式打标完全依赖文件名和目录路径正则，难度分层（4 easy + 14 hard）尤其是弱信号，存在误判可能。
- `estimated_position` 现已 62/62 非默认（公务员 40 / 广东选调、广东事业、广东省考、省考 合计 4 / 综合管理 18），但"公务员"与"综合管理"过于粗颗粒，仍需 LLM 精修到"广东省考"、"选调"等细分岗位。
- 尚无 `topic_tags`（热点主题标签），`estimated_content_type` 只有一个"方法论"主导类别，不具备区分度。

### P1 LLM 输出仍未结构化

- training suggestion 仍然依赖 prompt 硬约束，没有 Pydantic schema 做后处理校验。
- 复盘长度、缺失维度兜底、异常分数修正都还在 agent 逻辑里分散处理，没有集中的 schema 层。

### P1 抽题策略方向未定

- `repeated_weak_dimensions` 是做检索过滤器、reranker 权重，还是塞进 prompt 上下文，方向没选定。
- 没有这一步，`profile_eval` 就没法验证"画像是否真的驱动了下一轮抽题"。

### P1 live CLI 尚未在新状态下复验

- 标签补齐后，`mock_interview` 抽题应该更稳定地命中特定题型。
- RAG 检索日志目前不区分命中的是 `original_raw` 还是 `derived_ocr`，看不出 OCR 资料是否真的被利用。
