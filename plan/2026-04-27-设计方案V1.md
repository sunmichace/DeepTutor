# 公考面试 AI 教师平台的 AI 记忆与知识图谱设计方案

更新时间：2026-04-27

## 一、方案目的

本方案用于说明：如何参考已下载到本地的 AI 记忆相关开源项目，并结合 DeepTutor 当前的公考 / 事业编面试平台规划，设计一套适合本项目的长期记忆、考生画像、资料检索和知识图谱能力。

本方案不是代码实现文档，也不涉及具体代码、数据库语句或接口定义。它的目标是把产品需求、业务边界、开源项目可借鉴点和分阶段建设路线讲清楚，方便后续进入详细设计和开发排期。

本方案主要参照 `docs/public-exam-ai-teacher-plan.zh-CN.md` 中的以下内容：

- 产品定位：平台面向公考 / 事业编面试训练，不是通用学习平台，也不是笔试刷题平台。
- 核心目标：帮助考生学习真题、高分作答、老师方法论，并完成模拟面试、追问、评分和复盘。
- 长期目标：长期积累个人面试表现画像。
- 输入资料：往年真题、高分学生作答、老师方法论、热点材料、政策案例、岗位素材、示范音视频。
- 当前项目初始资料位置：平台输入资料已经放在项目的 `input/` 目录下，包括面试相关资料、95 分以上学员面试答题录音、老夏说面试课程笔记和视频课资料。
- 核心能力：资料学习能力、个性化训练能力、模拟面试考试能力。
- 当前基础：DeepTutor 已有知识库、TutorBot 角色化能力和两文件 Memory 基础。
- 当前缺口：缺少面试专用数据模型、模拟面试状态机、结构化评分、长期趋势分析和更精细的 learner profile。

本方案还需要满足一个更长期的平台目标：这是一个面向多个用户持续使用的训练平台，不是一次性资料问答工具。随着越来越多考生完成模拟面试、评分、追问和复盘，平台应当在保护个人隐私的前提下不断积累经验。它不仅要记住单个考生的成长轨迹，也要逐步沉淀出更好的题型理解、评分校准、常见失分模式和训练推荐策略，从而变得越来越“懂公考面试”、越来越“懂不同类型考生”。

## 二、核心需求

### 1. 资料学习需求

平台需要能够管理和利用三类核心资料：

| 资料类型 | 主要内容 | 对 AI 记忆 / 图谱的要求 |
| --- | --- | --- |
| 真题资料 | 结构化面试真题、无领导小组题、岗位匹配题、计划组织题、综合分析题、人际沟通题、应急应变题 | 能按题型、岗位、难度、热点标签检索 |
| 高分作答资料 | 高分学生完整作答、拆解版、高分结构模板、亮点总结 | 能用于对比、示范、生成改进建议 |
| 老师方法论资料 | 审题方法、立意方法、结构模板、展开方法、追问应对方法、常见失分点 | 能和题型、评分维度、失分点建立关联 |

这些资料本质上属于“公共知识”。它们适合进入资料库、RAG 检索系统和后续领域知识图谱，不应该混入某个用户的个人长期记忆。

当前项目中的初始平台资料位于 `input/` 目录，应作为第一批种子数据进行整理和入库。根据当前目录结构，至少包含：

- `input/面试相关`：面试相关基础资料和题库资料，可作为 Interview Bank 和 Methodology Bank 的初始来源。
- `input/95分以上学员面试答题录音`：高分学员真实答题录音，可作为 High Score Answer Bank 和表达示范资料的初始来源。
- `input/09.老夏说面试`：老师课程笔记和视频课资料，可作为 Methodology Bank、题型方法论和常见失分点总结的初始来源。

这些输入资料的处理目标不是简单“存文件”，而是形成平台可长期复用的公共知识底座。它们应逐步被整理成真题、题型、方法论、高分表达、常见失分点、评分维度和热点素材，供所有用户训练时复用。

### 2. 个性化训练需求

平台需要根据考生的历史表现建立长期画像，支持：

- 判断考生常见问题。
- 记录不同题型下的薄弱项。
- 记录不同评分维度的长期变化。
- 推荐下一步训练题型和训练重点。
- 给出更适合该考生的答题结构提示。
- 在模拟面试前让考官 Agent 了解该考生的历史问题。
- 在复盘报告中体现阶段性进步和持续短板。

这部分属于“用户记忆”。它需要结构化、可追踪、可更新、可清除，不能只依赖普通聊天摘要。

由于平台面向多个用户，个性化训练记忆必须做到用户隔离。每个考生都应拥有独立的 learner profile、训练历史和复盘记录。系统可以从多用户训练中总结平台级规律，但不能把某个用户的个人经历、身份信息或具体答题内容直接暴露给其他用户。

### 3. 模拟面试考试需求

原方案提出的模拟面试流程包括：

1. 选择面试类型、岗位方向、题型和难度。
2. 从 Interview Bank 抽题。
3. 用户作答，或由 AI 考生模拟作答。
4. AI 面试考官进行初评。
5. 必要时发起追问。
6. 用户或 AI 考生再次补答。
7. 评分 Agent 聚合评分。
8. 复盘 Agent 生成报告。
9. 将结果回写 learner profile。

AI 记忆系统要服务这个流程，而不是替代这个流程。它主要在两个位置发挥作用：

- 面试开始前：提供考生画像、近期薄弱项、相关方法论和高分样例。
- 面试结束后：沉淀本次表现、评分证据、追问问题、复盘建议和下一步训练计划。

## 三、AI 记忆与知识图谱的边界

本项目需要同时区分四类内容。

| 类型 | 说明 | 示例 | 建议处理方式 |
| --- | --- | --- | --- |
| 资料知识 | 面向所有考生共享的知识 | 真题、方法论、高分答案、政策热点 | 进入资料库和 RAG，后续进入领域图谱 |
| 用户记忆 | 某个考生长期变化的信息 | 薄弱题型、表达问题、评分趋势、训练偏好 | 进入 learner profile 和 memory facts |
| 面试过程状态 | 某一场模拟面试中的临时状态 | 当前题目、当前作答、追问轮次、评分草稿 | 由 mock_interview 状态机管理 |
| 平台经验 | 从多用户训练中抽象出的共性规律 | 常见失分模式、题型难度校准、追问策略效果、方法论提分效果 | 匿名化、聚合化后进入平台级知识沉淀 |

这四类内容不能混在一起。混在一起会带来三个问题：

- 公共资料和个人画像互相污染。
- 单场面试的临时状态被误当成长期事实。
- 检索时召回不准，导致个性化建议失真。

平台经验尤其需要谨慎处理。它可以帮助平台越来越聪明，但必须来自匿名化、聚合化后的训练数据，不能泄露单个用户的隐私。平台可以学习“多数考生在综合分析题中容易立意空泛”，但不应该把某个具体考生的原始答题暴露给其他用户。

## 四、面向本项目的记忆分层设计

### 1. 单轮记忆

作用：

- 保存当前用户输入。
- 保存当前 Agent 的临时分析。
- 保存工具或检索结果。

生命周期：

- 只在当前轮或当前节点有效。

适用场景：

- 用户刚刚回答了一道题。
- 考官正在判断是否追问。
- 评分 Agent 正在读取本轮作答。

### 2. 单场面试记忆

作用：

- 保存一场模拟面试的完整过程。
- 包括题目、作答、追问、补答、评分、报告。

生命周期：

- 至少保存到本场面试结束。
- 结束后转化为历史面试记录和长期表现事实。

适用场景：

- 面试中断恢复。
- 复盘报告生成。
- 后续查看历史记录。

### 3. 考生长期记忆

作用：

- 保存跨多场面试的长期表现画像。
- 记录稳定目标、薄弱项、表达习惯、训练偏好和评分趋势。

生命周期：

- 跨会话长期保存。
- 支持用户查看、清除和导出。

适用场景：

- 推荐下一场训练题型。
- 个性化追问。
- 个性化答题结构建议。
- 阶段性复盘。

### 4. 领域知识记忆

作用：

- 保存面试领域中的公共知识和关联关系。
- 包括题型、方法论、评分维度、失分点、高分表达、热点材料。

生命周期：

- 长期共享。
- 随资料更新而更新。

适用场景：

- 查找某题型的答题方法。
- 对比高分答案。
- 给出某个失分点对应的训练方法。
- 解释评分依据。

## 五、考生画像设计

考生画像建议拆为两部分。

### 1. 稳定画像

稳定画像记录长期有效的信息：

- 目标考试类型。
- 目标岗位方向。
- 当前备考阶段。
- 主要训练目标。
- 答题表达偏好。
- 是否需要模板化提示。
- 是否需要高分示范。

这些信息变化较慢，不应频繁覆盖。

### 2. 动态画像

动态画像记录近期训练状态：

- 最近薄弱题型。
- 最近低分评分维度。
- 最近常见扣分原因。
- 最近追问应答问题。
- 最近训练趋势。
- 当前建议训练重点。

这些信息会随训练变化，应定期更新。

## 六、面试记忆写入规则

长期记忆不能随意写入。只有对后续训练有价值的信息才应沉淀。

### 1. 应写入的内容

- 多次出现的薄弱题型。
- 明确影响分数的表达问题。
- 某个评分维度的持续低分。
- 某个评分维度的明显改善。
- 用户明确表达的目标岗位和备考阶段。
- 用户偏好的训练方式。
- 追问阶段暴露出的关键短板。
- 复盘报告中的下一步训练建议。

### 2. 不应写入的内容

- 单次偶然口误。
- 临时闲聊内容。
- 无关身份信息。
- 敏感个人信息。
- 未经确认的高风险推断。
- Agent 自己不可靠的猜测。

### 3. 写入时机

推荐在以下节点写入：

- 一场模拟面试结束后。
- 复盘报告生成后。
- 用户主动要求保存训练结论时。
- 系统发现某个问题在多场训练中反复出现时。

不推荐每一轮对话都写入长期记忆。这样会造成噪声过多，后续检索和画像都会变差。

## 七、面试开始前如何使用记忆

在进入模拟面试前，系统应根据当前训练配置读取相关上下文。

需要读取的信息包括：

- 考生稳定画像。
- 考生近期动态画像。
- 最近几场同题型训练表现。
- 当前题型下的历史扣分点。
- 当前岗位方向相关素材。
- 当前题型对应的老师方法论。
- 可参考的高分作答片段。

这些信息应分角色提供给不同 Agent：

| Agent | 需要看到的记忆 |
| --- | --- |
| AI 考生 | 考生水平、作答风格、参考作答目标 |
| 面试考官 | 评分规则、历史薄弱项、追问策略 |
| 评分 Agent | 本场完整作答、评分维度、证据材料 |
| 复盘 Agent | 本场表现、历史趋势、下一步训练建议 |

## 八、面试结束后如何沉淀记忆

面试结束后，系统应把一次训练拆成三类结果。

### 1. 历史记录

用于完整复盘：

- 本场题目。
- 用户答题。
- 追问问题。
- 用户补答。
- 分维度评分。
- 复盘报告。

### 2. 长期事实

用于未来个性化：

- 用户在某题型下的薄弱项。
- 用户在某评分维度上的变化。
- 用户在追问阶段的问题。
- 用户适合的训练建议。

### 3. 画像更新

用于快速注入上下文：

- 稳定画像只在明确变化时更新。
- 动态画像根据最近训练自动更新。
- 画像更新必须保留来源，避免无依据结论。

## 九、知识图谱设计方向

第一阶段不强制建设完整知识图谱，但需要从设计上预留关系结构。

### 1. 领域图谱

领域图谱描述公共知识之间的关系：

- 某题型对应哪些答题方法。
- 某题型常见哪些失分点。
- 某评分维度对应哪些训练方法。
- 某高分答案片段示范了哪种表达结构。
- 某热点材料适用于哪些题型。

### 2. 学员图谱

学员图谱描述某个考生和训练结果之间的关系：

- 考生练过哪些题型。
- 考生在哪些维度持续低分。
- 考生哪些问题已经改善。
- 考生适合哪些训练方法。
- 考生下一步应该练什么。

### 3. 两类图谱的结合

真正有价值的是把学员图谱和领域图谱连起来。

例如：

- 考生在综合分析题中立意薄弱。
- 综合分析题的立意薄弱可以用某种老师方法论改善。
- 某个高分答案片段正好示范了这种方法论。
- 系统因此推荐该方法论和对应训练题。

这样系统给出的建议就不是泛泛而谈，而是有来源、有路径、有解释。

## 十、多用户平台的持续学习机制

本平台不是单用户助手，而是面向多个考生长期使用的训练平台。AI 记忆系统需要同时服务两个层面的成长：

- 单个考生越来越被理解。
- 整个平台越来越懂公考面试。

### 1. 单个考生层面的成长

随着某个考生不断训练，平台应逐步积累：

- 该考生的目标岗位和备考阶段。
- 该考生常见薄弱题型。
- 该考生在各评分维度上的变化趋势。
- 该考生常见表达问题。
- 该考生对追问的应对能力。
- 该考生适合的训练节奏和提示方式。

这种成长体现在个性化体验上：

- 下一次训练更容易选到合适难度和题型。
- 面试考官能更有针对性地追问。
- 复盘报告不只是评价本次表现，还能比较历史变化。
- 训练建议能围绕长期短板持续推进。

### 2. 平台公共能力层面的成长

随着多个用户持续使用，平台还应逐步沉淀匿名化、聚合化的公共经验：

- 哪些题型最容易失分。
- 哪些评分维度最常见问题。
- 哪些追问策略最能暴露真实短板。
- 哪些老师方法论对哪些失分点更有效。
- 哪些高分答案片段最适合作为示范。
- 不同岗位方向的题目难度和评分侧重点。

这些平台经验可以反哺公共能力：

- 改进题型分类。
- 改进评分 rubric。
- 改进追问策略。
- 改进训练推荐。
- 改进高分答案示范选择。
- 改进方法论和失分点之间的匹配。

### 3. 个人记忆与平台经验的隔离

平台越用越聪明，前提是不能牺牲用户隐私。

必须坚持：

- 个人画像只服务该用户本人。
- 原始答题内容默认不进入平台公共经验。
- 平台级规律必须来自匿名化和聚合化统计。
- 不能让一个用户看到另一个用户的具体训练记录。
- 高分学员答题资料如果用于示范，应来自明确授权或平台输入资料。
- 平台经验只能沉淀共性模式，不能沉淀可识别个人身份的信息。

### 4. 平台学习闭环

理想闭环如下：

1. 平台从 `input/` 中获得第一批真题、高分作答、老师方法论和示范材料。
2. 用户基于这些资料进行模拟面试训练。
3. 每场训练产生作答、追问、评分和复盘。
4. 系统把结果写入该用户的个人 learner profile。
5. 系统从多用户训练中抽象匿名化共性规律。
6. 共性规律反哺题库、方法论、评分、追问和推荐策略。
7. 新用户和老用户都获得更好的训练体验。

这个闭环是本项目 AI 记忆系统的长期价值所在。第一阶段可以先做个人画像和历史复盘，后续再逐步建设平台级经验沉淀。

## 十一、与原方案各模块的结合

### 1. 与资料导入能力结合

原方案建议新增 `pdf_to_markdown_ingest`，用于将 PDF 面试资料转成 Markdown，再通过 LLM 整理后分类入库。

在 AI 记忆方案中，这一能力应继续服务资料库建设：

- `input/面试相关` 中的资料优先进入 Interview Bank 和 Methodology Bank。
- `input/95分以上学员面试答题录音` 中的资料优先转写、切分并进入 High Score Answer Bank。
- `input/09.老夏说面试` 中的课程笔记和视频课资料优先进入 Methodology Bank 和失分点总结库。
- 真题进入 Interview Bank。
- 高分作答进入 High Score Answer Bank。
- 老师方法论进入 Methodology Bank。
- 热点和政策材料进入 Hot Topic Material Bank。

资料导入阶段应尽量提取题型、岗位、难度、热点、方法论、评分维度等标签，为后续检索和图谱建设打基础。

### 2. 与 TutorBot 角色化能力结合

原方案指出 TutorBot 已支持独立 workspace、独立 persona、共享 memory 和独立会话历史。

在 AI 记忆方案中，可以用 TutorBot 构建不同面试角色：

- 面试考官。
- 面试陪练官。
- 方法论老师。
- 复盘点评老师。

但这些角色不应该共享同一份无差别记忆。不同角色应读取不同范围的记忆，避免角色混淆。

### 3. 与现有 Memory 基础结合

当前 Memory 系统维护 `SUMMARY.md` 和 `PROFILE.md`，适合作为通用学习记忆入口。

在本项目中：

- 可以继续保留这套通用记忆。
- 面试画像应建立专用结构化存储。
- 只把少量高层结论同步到通用 Profile。
- 详细评分、追问记录、历史报告应进入面试专用记忆。

### 4. 与 mock_interview 能力结合

原方案中 `mock_interview` 是核心能力，负责“出题、答题、追问、评分、复盘”的流程。

AI 记忆在其中承担两类职责：

- 流程开始前提供个性化上下文。
- 流程结束后沉淀长期训练结果。

面试流程控制仍然由 `mock_interview` 状态机负责，长期记忆不直接控制流程。

### 5. 与评分 Rubric 结合

原方案建议评分维度包括：

- 审题与立意。
- 结构化表达。
- 逻辑完整性。
- 论据与案例质量。
- 岗位匹配度。
- 语言自然度。
- 临场应对。
- 追问应答质量。

AI 记忆系统应围绕这些维度沉淀长期数据。

例如：

- 用户最近三次“结构化表达”持续偏低。
- 用户“论据与案例质量”有明显提升。
- 用户“追问应答质量”仍不稳定。

这些结论可以用于下一次训练的题目选择、追问策略和复盘重点。

## 十二、开源项目如何支撑本方案

本方案不把某个开源库作为整体运行时直接引入，而是按方案能力拆解参考。这样既能吸收成熟项目的设计经验，又能保持 DeepTutor 现有架构边界。

| 本方案部分 | 参考项目 | 参考内容 | 落到本项目的设计取舍 |
| --- | --- | --- | --- |
| 记忆分层 | `/hdd/project/mem0`、`/hdd/project/supermemory` | user/session/agent/run_id 分层；Memory 与 RAG 区分 | 本项目拆为资料知识、用户记忆、面试过程状态、平台经验 |
| 考生画像 | `/hdd/project/supermemory`、`/hdd/project/letta` | static/dynamic profile；core memory block | 本项目拆为稳定画像和动态画像，并按角色注入不同 Agent |
| 面试记忆写入 | `/hdd/project/mem0` | 事实记忆、来源记录、异步归纳、用户级隔离 | 本项目只在面试结束、复盘生成、重复问题出现等关键节点写入 |
| 面试前上下文组装 | `/hdd/project/letta`、`/hdd/project/mem0` | 短核心记忆 + 检索补充；多信号召回 | 本项目为 AI 考生、面试考官、评分 Agent、复盘 Agent 提供不同上下文 |
| 知识图谱 | `/hdd/project/zep`、Graphiti 思路、`/hdd/project/supermemory` | temporal graph、关系检索、更新/补充/推导关系 | 本项目先做轻量关系设计，后续再考虑完整图谱服务 |
| 多用户平台经验 | `/hdd/project/supermemory`、`/hdd/project/zep` | 用户 profile 与平台经验分离；事实随时间变化 | 本项目只沉淀匿名化、聚合化规律，不暴露个人训练记录 |
| 记忆管理与隐私 | `/hdd/project/mem0/openmemory` | 记忆查看、筛选、删除、导出 | 本项目后续提供“我的面试画像”和“我的复盘历史”管理能力 |
| 面试状态机 | `/hdd/project/langgraph` | 长流程状态、条件分支、中断恢复 | 本项目只在 `mock_interview` 内部参考其状态机思想，不替换全局编排 |

### 1. 记忆分层参考 mem0 与 Supermemory

mem0 的核心价值是把记忆按用户、会话、Agent 和任务进行隔离，并把长期记忆设计为可写入、可检索、可更新的事实集合。Supermemory 的核心价值是明确区分资料检索和用户记忆，避免把静态资料当成个人记忆。

本项目据此确定：

- `input/` 中的真题、高分答案、老师方法论属于资料知识。
- 单个考生的薄弱项、评分趋势和训练偏好属于用户记忆。
- 单场面试中的题目、作答、追问和评分草稿属于过程状态。
- 多用户训练中抽象出的常见失分模式属于平台经验。

### 2. 考生画像参考 Supermemory 与 Letta

Supermemory 的 static profile 和 dynamic profile 思路适合本项目的考生画像。Letta 的 memory block 思路适合指导 Agent 读取画像的方式。

本项目据此确定：

- 稳定画像记录目标岗位、备考阶段、训练偏好等长期稳定信息。
- 动态画像记录近期薄弱项、最近低分维度、训练趋势等会变化的信息。
- 面试考官、AI 考生、评分 Agent、复盘 Agent 读取不同画像视图。

### 3. 记忆写入参考 mem0

mem0 强调长期记忆不是简单保存聊天记录，而是提取有价值的事实，并通过用户维度隔离。这个思路适合本项目的面试复盘沉淀。

本项目据此确定：

- 不在每轮对话后都写长期记忆。
- 只在面试结束、复盘生成、用户主动保存、重复问题出现时写入。
- 每条长期结论都需要有来源，避免无依据画像。
- 个人记忆只服务该用户本人。

### 4. 知识图谱参考 Zep / Graphiti 与 Supermemory

Zep / Graphiti 的价值在于时间化关系图，适合描述事实如何随时间变化。Supermemory 的图记忆强调更新、补充和推导关系，适合描述旧结论如何被新训练结果修正。

本项目据此确定：

- 第一阶段不直接建设完整图数据库。
- 先在方案层明确领域图谱和学员图谱的关系。
- 后续再把题型、方法论、评分维度、失分点、高分答案片段和用户表现连接起来。
- 图谱的最终价值是解释“为什么推荐这个题型、这个方法论、这个训练计划”。

### 5. 记忆管理参考 OpenMemory

OpenMemory 的价值在于让用户能够看到、管理和控制自己的记忆。

本项目据此确定：

- 后续应提供“我的面试画像”。
- 后续应提供“我的复盘历史”。
- 用户应能查看、清除、导出自己的面试记忆。
- 平台经验只能使用匿名化聚合结果，不能泄露个人记录。

### 6. 面试流程参考 LangGraph

LangGraph 的价值在于长流程状态机、条件分支和中断恢复。原方案已经明确 `mock_interview` 适合局部使用状态机。

本项目据此确定：

- 单场面试流程状态由 `mock_interview` 管理。
- 长期记忆系统不直接控制面试流程。
- 面试结束后的评分和复盘才进入长期记忆。
- 不把 LangGraph 升级为 DeepTutor 全局编排器。

## 十三、分阶段建设路线

### P0：结构化面试记忆 MVP

目标：

- 让平台能保存每场模拟面试结果。
- 让平台能形成基础考生画像。
- 让下一场训练能读取历史薄弱项。
- 让 `input/` 中已有资料成为第一批可检索、可复用的平台知识。

范围：

- 建立面试专用历史记录。
- 建立稳定画像和动态画像。
- 保存分维度评分和复盘报告。
- 支持面试开始前读取相关画像。
- 支持面试结束后更新画像。
- 整理 `input/` 中的初始面试资料，形成基础真题库、高分作答库和方法论库。

不做：

- 不引入完整外部 memory runtime。
- 不引入完整图数据库。
- 不做复杂记忆管理 UI。

主要参考：

- 参考 mem0 的用户级记忆隔离和事实记忆写入。
- 参考 Supermemory 的 Memory 与 RAG 边界。
- 参考 Letta 的角色化记忆视图。

### P1：检索增强与轻量关系图

目标：

- 提升历史表现召回质量。
- 让系统能解释为什么推荐某个训练方向。
- 让方法论、高分答案和用户薄弱项产生关联。
- 开始沉淀匿名化的平台级共性经验。

范围：

- 增强历史记忆检索。
- 增加题型、评分维度、薄弱项、方法论之间的轻量关系。
- 增加用户可见的面试画像页面。
- 支持用户清除和导出个人面试记忆。
- 基于多用户训练结果统计常见失分点和高频薄弱题型。

主要参考：

- 参考 mem0 的多信号检索和实体关联。
- 参考 OpenMemory 的记忆管理体验。
- 参考 Zep / Graphiti 的轻量关系表达。

### P2：时间化知识图谱与高级个性化

目标：

- 建立完整领域图谱和学员图谱。
- 支持长期趋势分析。
- 支持更强的解释型推荐。
- 让平台级经验持续反哺评分、追问、题目推荐和方法论推荐。

范围：

- 引入更完整的图谱存储或图谱服务。
- 记录事实的有效时间和失效时间。
- 分析薄弱项是否改善。
- 分析方法论是否真正帮助用户提分。
- 支持多考官 Agent 评分校准。
- 建设匿名化平台经验库，用于优化公共训练策略。

主要参考：

- 参考 Zep / Graphiti 的时间化图谱。
- 参考 Supermemory 的更新、补充、推导关系。
- 参考 LangGraph 的长流程状态恢复经验，但仍限制在面试流程内部。

## 十四、评测要求

AI 记忆必须有评测，否则容易出现“看起来记住了，实际召回错误”的问题。

建议评测以下能力：

| 评测项 | 说明 |
| --- | --- |
| 画像准确性 | 是否正确总结考生长期目标和稳定偏好 |
| 薄弱项召回 | 是否能召回真实反复出现的问题 |
| 证据支撑 | 是否能指出结论来自哪次训练或哪类评分 |
| 旧事实处理 | 是否避免使用已经过时的结论 |
| 推荐合理性 | 推荐的题型和方法论是否符合历史表现 |
| 上下文控制 | 注入给 Agent 的记忆是否简洁、相关、不过量 |
| 多用户隔离 | 一个用户的个人记忆是否不会泄露给其他用户 |
| 平台经验质量 | 多用户聚合规律是否真实提升题目推荐和复盘质量 |

评测样例应覆盖：

- 不同岗位方向。
- 不同题型。
- 多场训练历史。
- 表现进步和退步。
- 旧结论被新结论更新。
- 用户清除记忆后的行为。
- 多个用户同时使用时的记忆隔离。
- 平台经验反哺后的推荐效果变化。

## 十五、隐私与治理要求

因为本系统会长期记录考生表现，必须从第一阶段就考虑隐私和治理。

基本要求：

- 用户可以查看自己的面试画像。
- 用户可以清除自己的面试记忆。
- 用户可以导出自己的历史复盘。
- 系统应记录每条长期结论的来源。
- 低置信度推断不能写入稳定画像。
- 敏感信息不能进入长期记忆。
- 原始音视频不应默认长期保存。
- 多用户聚合分析必须匿名化。
- 平台公共经验不能包含可识别个人身份的信息。

## 十六、最终建议

本项目第一阶段应优先建设 DeepTutor 原生的面试专用记忆层，而不是直接引入某个外部开源库作为运行时。

推荐路线：

- 先把 `input/` 中已有的面试相关资料、高分学员录音、老夏说面试课程资料整理为平台第一批公共知识。
- 用 DeepTutor 现有知识库能力承载真题、高分答案、老师方法论和热点材料。
- 用面试专用结构化记忆承载 learner profile、评分历史、薄弱项和复盘结论。
- 用多用户匿名化聚合结果沉淀平台经验，让平台随着使用逐步变聪明。
- 用 `mock_interview` 状态机管理单场面试流程。
- 开源项目只作为设计参考，不作为第一阶段的整体替代方案。

这样可以最大限度贴合 `docs/public-exam-ai-teacher-plan.zh-CN.md` 的核心目标：围绕公考 / 事业编面试训练，长期积累个人面试表现画像，并将 `input/` 中已有平台资料、真题、高分作答、老师方法论、评分复盘、多用户训练经验和个性化训练串成一个可持续演进的系统。
