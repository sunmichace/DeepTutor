# 公考面试 AI 教师平台的 AI 记忆与知识图谱落地方案

更新时间：2026-04-27

## 一、落地目标

本落地方案承接 `plan/2026-04-27-设计方案.md`，用于把 AI 记忆与知识图谱设计转化为可执行的建设步骤、阶段交付物、验收标准和风险控制。

本方案仍然是纯方案文档，不包含代码、数据库语句或接口定义。它重点回答：

- `input/` 中已有平台资料如何变成可复用知识。
- 多用户平台如何在保护隐私的前提下持续变聪明。
- 单个考生的 learner profile 如何从训练中逐步成长。
- AI 记忆如何接入模拟面试、评分、追问和复盘流程。
- 已下载开源项目的设计经验如何落到每个建设阶段。

最终目标是形成一个持续演进的公考 / 事业编面试训练平台：

- 初始阶段依赖 `input/` 中的真题、高分作答、课程资料和方法论。
- 用户训练后沉淀个人画像和历史复盘。
- 多用户持续使用后沉淀匿名化平台经验。
- 平台逐步提升题型理解、评分校准、追问策略、训练推荐和复盘质量。

## 二、落地原则

### 1. 先业务闭环，再技术增强

第一阶段不追求完整知识图谱，也不追求引入复杂外部记忆框架。优先打通最小闭环：

- 平台资料可检索。
- 用户可模拟面试。
- 系统可评分和复盘。
- 复盘结果可回写个人画像。
- 下一次训练能读取历史画像。

### 2. 先个人记忆，再平台经验

个人 learner profile 是 P0 必须完成的核心。平台级经验需要足够多用户训练数据，适合 P1/P2 再逐步沉淀。

### 3. 先隔离，再共享

平台面向多个用户，必须先保证用户记忆隔离。只有经过匿名化、聚合化处理后的共性规律，才能进入平台经验。

### 4. 先资料库，再图谱

`input/` 中的资料先整理为可检索的真题库、高分作答库、方法论库和热点材料库。图谱建设应建立在这些资料已经被结构化整理的基础上。

### 5. 开源项目只作参考，不替换 DeepTutor 架构

mem0、OpenMemory、Zep、Letta、Supermemory、LangGraph 只作为设计参考。第一阶段不直接用它们替换 DeepTutor 的 orchestrator、capability、TutorBot、Memory 和 RAG 体系。

## 三、总体落地路径

建议按三阶段推进。

| 阶段 | 目标 | 核心成果 |
| --- | --- | --- |
| P0 | 跑通资料入库、模拟面试、评分复盘、个人画像回写 | 平台能基于 `input/` 资料训练单个用户，并记住该用户表现 |
| P1 | 增强检索、关系表达、多用户匿名化经验 | 平台能解释推荐原因，并从多用户训练中总结共性规律 |
| P2 | 建设时间化知识图谱和高级个性化 | 平台能长期分析趋势、校准评分、优化追问和训练策略 |

## 四、P0：结构化面试记忆 MVP

### 1. 阶段目标

P0 的目标是把平台从“有资料、有对话能力”推进到“能完成一场可复盘、可记忆、可延续的模拟面试”。

P0 完成后，平台应具备：

- 能读取和整理 `input/` 中已有面试资料。
- 能形成基础 Interview Bank、High Score Answer Bank、Methodology Bank。
- 能完成文本版模拟面试。
- 能根据 rubric 生成分维度评分。
- 能生成复盘报告。
- 能沉淀用户个人 learner profile。
- 能在下一次训练中读取历史薄弱项和建议。

### 2. 输入资料落地

P0 先处理 `input/` 中三类资料。

| 输入目录 | 落地目标 | 第一阶段处理重点 |
| --- | --- | --- |
| `input/面试相关` | 形成真题库和基础方法论库 | 识别题目、题型、岗位方向、难度、热点标签 |
| `input/95分以上学员面试答题录音` | 形成高分作答库和表达示范库 | 转写、切分、提取高分结构、亮点表达和示范片段 |
| `input/09.老夏说面试` | 形成老师方法论库和失分点库 | 整理题型方法、答题框架、常见失分点、追问应对方法 |

P0 不要求资料整理一次性完美，但需要形成可持续补充的资料标准。

每条资料至少要能回答：

- 它属于真题、高分作答、方法论还是热点材料。
- 它对应什么题型。
- 它适合什么岗位或场景。
- 它能用于出题、示范、评分还是复盘。
- 它是否可以被所有用户共享。

### 3. 面试流程落地

P0 的模拟面试采用文本流程，先覆盖最小闭环：

1. 用户选择面试类型、岗位方向、题型和难度。
2. 平台从真题库抽题，或基于真题生成相似题。
3. 用户进行文本作答。
4. 面试考官根据 rubric 初评。
5. 系统判断是否追问。
6. 用户补答。
7. 评分 Agent 汇总分维度评分。
8. 复盘 Agent 输出复盘报告。
9. 记忆写入器沉淀用户本场表现。
10. learner profile 更新。

P0 可以先限制追问轮次，保证流程稳定。追问策略先以“暴露薄弱项”为目标，不追求复杂多轮博弈。

### 4. 个人画像落地

P0 中 learner profile 至少分为两部分。

稳定画像：

- 目标考试类型。
- 目标岗位方向。
- 当前备考阶段。
- 训练偏好。
- 是否需要模板化提示。
- 是否需要高分示范。

动态画像：

- 最近薄弱题型。
- 最近低分评分维度。
- 最近常见扣分原因。
- 最近追问应答问题。
- 当前训练建议。
- 最近训练趋势。

P0 的重点不是画像字段多，而是画像必须可被下一次训练使用。

### 5. 记忆写入落地

P0 只在明确节点写入长期记忆。

应写入：

- 本场面试题型。
- 分维度评分。
- 关键扣分原因。
- 关键优点。
- 追问暴露的问题。
- 复盘建议。
- 下一步训练建议。

不写入：

- 临时闲聊。
- 单次偶然口误。
- 无评分依据的猜测。
- 敏感个人信息。
- 用户未授权的原始音视频长期内容。

P0 的写入原则参考 mem0：长期记忆不是完整聊天记录，而是可复用的事实和结论。

### 6. 面试前记忆读取落地

下一场训练开始前，系统需要读取：

- 用户稳定画像。
- 用户动态画像。
- 最近几次同题型表现。
- 当前题型历史低分维度。
- 当前题型相关老师方法论。
- 可参考高分答案片段。

不同 Agent 获取不同上下文：

| Agent | P0 读取重点 |
| --- | --- |
| AI 考生 | 用户当前水平、作答目标、参考风格 |
| 面试考官 | 题目、rubric、历史薄弱项、追问策略 |
| 评分 Agent | 本场完整答题、评分维度、扣分证据 |
| 复盘 Agent | 本场评分、历史趋势、下一步训练建议 |

这个设计参考 Letta 的角色化记忆块：不同角色不应看到完全相同的记忆。

### 7. P0 交付物

P0 完成时应交付：

- 初始资料整理规则。
- 真题库、高分作答库、方法论库的基础版本。
- 文本模拟面试流程。
- 基础评分 rubric。
- 复盘报告模板。
- learner profile 规则。
- 面试记忆写入规则。
- 面试前上下文读取规则。
- 用户记忆隔离规则。
- P0 验收用样例集。

### 8. P0 验收标准

P0 至少满足：

- 能从 `input/` 资料中抽取或整理一批可用真题和方法论。
- 用户能完成一场完整文本模拟面试。
- 系统能给出分维度评分和复盘报告。
- 用户完成多场训练后，系统能总结稳定薄弱项。
- 用户再次训练时，系统能引用历史薄弱项进行追问或建议。
- 不同用户之间的画像和历史记录互不混用。
- 复盘结论有来源，不出现无依据长期画像。

### 9. P0 主要风险

| 风险 | 表现 | 控制方式 |
| --- | --- | --- |
| 资料质量不稳定 | PDF、录音、课程资料整理结果混乱 | 先建立人工可校对的资料整理标准 |
| 评分不稳定 | 同一答案多次评分差异过大 | 固定 rubric，保留扣分原因和证据 |
| 画像噪声过多 | 单次偶然问题被写入长期画像 | 只写高价值事实，多次出现的问题优先 |
| 用户隔离不足 | 多用户记忆串用 | 所有个人记忆必须绑定用户身份 |
| 上下文过长 | 面试前塞入过多历史 | 只注入最近、相关、高价值内容 |

## 五、P1：检索增强与轻量关系图

### 1. 阶段目标

P1 的目标是让平台从“能记住用户”升级到“能解释为什么这样训练”。

P1 完成后，平台应具备：

- 更准确地召回历史薄弱项。
- 能把题型、方法论、评分维度、失分点、高分答案片段关联起来。
- 能基于多个用户的训练结果沉淀匿名化共性规律。
- 能提供用户可见的记忆管理能力。

### 2. 检索增强落地

P1 的检索不应只依赖语义相似度，而应综合：

- 题型标签。
- 岗位方向。
- 评分维度。
- 历史低分原因。
- 最近训练时间。
- 方法论匹配程度。
- 高分答案示范价值。

这部分参考 mem0 的多信号检索思想：语义召回、关键词、实体和上下文过滤应共同决定结果。

### 3. 轻量关系图落地

P1 不一定上完整图数据库，但要开始显式表达关系。

重点关系包括：

- 题型和方法论的关系。
- 题型和常见失分点的关系。
- 评分维度和训练建议的关系。
- 用户薄弱项和方法论的关系。
- 高分答案片段和表达结构的关系。
- 追问问题和暴露短板的关系。

这些关系的目标是让系统能解释：

- 为什么推荐这个题型。
- 为什么推荐这个方法论。
- 为什么本次追问是合理的。
- 为什么这个高分片段适合作为示范。

### 4. 多用户平台经验落地

P1 开始沉淀匿名化平台经验。

可以沉淀：

- 某题型最常见的失分点。
- 某岗位方向常见训练需求。
- 某评分维度最常见扣分原因。
- 某类追问最能暴露的问题。
- 某些方法论对某些问题更有效。

不能沉淀：

- 个人原始答题。
- 可识别用户身份的信息。
- 未匿名化的训练记录。
- 单个用户的隐私化经历。

平台经验的目标不是评价某个用户，而是反哺公共训练能力。

### 5. 用户记忆管理落地

P1 应提供用户可见的记忆管理能力。

用户应能看到：

- 我的稳定画像。
- 我的动态画像。
- 我的历史训练记录。
- 我的主要薄弱项。
- 我的近期进步。
- 我的下一步训练建议。

用户应能操作：

- 清除个人面试记忆。
- 导出历史复盘。
- 查看某个画像结论的来源。
- 对错误画像进行反馈。

这部分参考 OpenMemory 的用户可控记忆管理思想。

### 6. P1 交付物

P1 完成时应交付：

- 增强检索规则。
- 轻量关系图设计。
- 题型、方法论、失分点、rubric 之间的关系样例。
- 用户记忆管理页面或等价管理能力。
- 匿名化平台经验沉淀规则。
- 训练推荐解释模板。
- P1 评测样例集。

### 7. P1 验收标准

P1 至少满足：

- 用户问“我为什么综合分析题分数低”，系统能结合历史训练和评分证据回答。
- 用户问“下一步练什么”，系统能基于画像、历史表现和题型覆盖给出建议。
- 系统能解释某条方法论推荐来自哪个失分点。
- 系统能引用高分答案片段作为示范。
- 用户能查看、导出、清除自己的面试记忆。
- 多用户平台经验不包含可识别个人信息。

### 8. P1 主要风险

| 风险 | 表现 | 控制方式 |
| --- | --- | --- |
| 检索结果看似相关但不可用 | 找到相似文本，却不能支撑建议 | 增加题型、rubric、岗位等结构化过滤 |
| 关系图过早复杂化 | 维护成本高，收益不明显 | 先表达核心关系，不追求完整知识图谱 |
| 平台经验误伤个体 | 用群体规律覆盖个人情况 | 平台经验只能辅助，个人画像优先 |
| 记忆管理体验复杂 | 用户不知道哪些能删 | 使用“画像、历史、建议”三类入口 |

## 六、P2：时间化知识图谱与高级个性化

### 1. 阶段目标

P2 的目标是让平台从“能解释当前推荐”升级到“能理解长期变化”。

P2 完成后，平台应具备：

- 能分析用户薄弱项是否改善。
- 能判断某方法论是否真的帮助用户提分。
- 能根据长期趋势调整训练路线。
- 能基于平台级经验优化评分、追问和推荐。
- 能把领域图谱和学员图谱连接起来。

### 2. 时间化关系落地

P2 应重点处理时间变化。

需要表达：

- 用户过去薄弱，但现在改善了。
- 用户某个问题反复出现，仍未解决。
- 某条训练建议已经过时。
- 某个方法论对某类用户有效。
- 某个评分维度经过训练持续提升。

这部分参考 Zep / Graphiti 的时间化图谱思想，也参考 Supermemory 的更新、补充和推导关系。

### 3. 领域图谱落地

领域图谱应逐步覆盖：

- 题型。
- 岗位方向。
- 方法论。
- rubric 维度。
- 常见失分点。
- 高分表达片段。
- 热点材料。
- 追问策略。

领域图谱的目标是支撑公共教学能力。

### 4. 学员图谱落地

学员图谱应逐步覆盖：

- 用户训练过哪些题型。
- 哪些题型持续薄弱。
- 哪些评分维度持续提升。
- 哪些方法论已经训练过。
- 哪些建议已完成。
- 哪些追问暴露了新问题。

学员图谱的目标是支撑个人长期成长。

### 5. 图谱结合落地

P2 的核心价值来自两类图谱连接。

示例：

- 用户在综合分析题中“审题与立意”持续低分。
- 领域图谱显示该问题常对应“现象定性不准”和“治理目标缺失”。
- 方法论库中存在对应训练方法。
- 高分作答库中存在示范片段。
- 系统推荐专项训练题和高分片段。
- 用户训练后该维度得分上升。
- 平台记录该方法论对该用户有效。

这类闭环让平台从“给建议”升级为“验证建议是否有效”。

### 6. P2 交付物

P2 完成时应交付：

- 时间化关系规则。
- 领域图谱规则。
- 学员图谱规则。
- 图谱解释型推荐模板。
- 长期趋势复盘模板。
- 方法论有效性分析规则。
- 平台级评分校准规则。
- P2 长期评测集。

### 7. P2 验收标准

P2 至少满足：

- 系统能说明某个薄弱项从什么时候开始出现，最近是否改善。
- 系统能解释为什么推荐某个方法论和高分片段。
- 系统能基于长期趋势调整训练计划。
- 系统能区分过时结论和当前有效结论。
- 系统能用匿名化平台经验改善公共题目推荐。
- 系统能评估某类方法论对某类失分点是否有效。

### 8. P2 主要风险

| 风险 | 表现 | 控制方式 |
| --- | --- | --- |
| 图谱复杂度失控 | 实体、关系越来越多但不可维护 | 只保留能支撑推荐、评分、复盘的关系 |
| 时间化事实冲突 | 新旧结论互相矛盾 | 明确当前有效、历史有效、已失效状态 |
| 平台经验偏差 | 使用样本不足导致错误规律 | 引入最小样本量和人工审核机制 |
| 解释过度 | 系统给出看似合理但无证据解释 | 所有解释必须能追溯到资料、评分或历史表现 |

## 七、跨阶段任务拆解

### 1. 资料治理任务

目标：让 `input/` 中的资料变成平台公共知识底座。

任务：

- 梳理 `input/` 下所有资料类型。
- 区分真题、高分作答、方法论、热点材料、示范音视频。
- 统一题型标签。
- 统一岗位方向标签。
- 统一评分维度标签。
- 为资料建立可校对的整理结果。
- 定期补充和修正资料库。

交付：

- 资料分类规范。
- 题型标签规范。
- 岗位标签规范。
- 高分作答拆解规范。
- 方法论整理规范。

### 2. 用户记忆任务

目标：让每个用户都有可持续成长的 learner profile。

任务：

- 设计稳定画像内容。
- 设计动态画像内容。
- 设计面试结束后写入规则。
- 设计画像更新频率。

### 3. 面试流程任务

## 十、风险与控制

| 风险 | 阶段 | 控制方式 |
| --- | --- | --- |
| 资料质量不稳定 | P0 | 先做小批量资料整理和人工校对 |
| 评分不可信 | P0 | 固定 rubric，保留扣分证据，允许人工抽查 |
| 画像污染 | P0/P1 | 只写高价值事实，低置信度结论不进稳定画像 |
| 用户记忆串用 | P0/P1/P2 | 坚持用户隔离，评测多用户访问边界 |
| 平台经验泄露隐私 | P1/P2 | 只使用匿名化和聚合化结果 |
| 图谱过早复杂化 | P1/P2 | 先轻量关系，后完整图谱 |
| 推荐越来越偏 | P1/P2 | 加入评测和人工审核机制 |
| 上下文过长 | P0/P1/P2 | 区分 Agent 角色，只注入必要记忆 |

## 十一、验收路线

### 1. P0 验收

用 3 到 5 个模拟用户完成连续训练。

每个用户至少完成：

- 3 场不同题型训练。
- 1 场同题型重复训练。
- 1 次追问和补答。
- 1 份完整复盘报告。

验收通过条件：

- 系统能记录个人历史表现。
- 系统能总结用户薄弱项。
- 系统能在下一场训练中使用历史记忆。
- 不同用户画像互不影响。
- 复盘建议能追溯到本场表现或历史表现。

### 2. P1 验收

用 10 到 30 个模拟用户和一批真实资料样例验证。

验收通过条件：

- 系统能解释训练推荐原因。
- 系统能用方法论匹配薄弱项。
- 系统能引用高分片段进行示范。
- 用户能查看和管理自己的记忆。
- 平台能产出匿名化常见失分统计。

### 3. P2 验收

用更长周期训练数据验证。

验收通过条件：

- 系统能分析薄弱项是否改善。
- 系统能识别过时结论。
- 系统能判断方法论对某类问题是否有效。
- 系统能用平台经验优化训练推荐。
- 图谱解释能追溯到资料、评分或历史训练。

## 十二、最终落地建议

建议从 P0 开始，先不要追求完整知识图谱和外部 memory runtime。第一步应集中在三个闭环：

- `input/` 资料整理成平台公共知识。
- 单个用户完成模拟面试后形成 learner profile。
- 下一次训练能使用历史记忆改进出题、追问和复盘。

当这个闭环稳定后，再进入 P1 做检索增强、轻量关系图和用户记忆管理。最后再进入 P2 做时间化知识图谱、长期趋势分析和平台级经验反哺。

这条路径能最大程度降低工程复杂度，同时保留平台长期变聪明的空间。
