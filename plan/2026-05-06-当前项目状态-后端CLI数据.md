## 一、已经完成的部分

### 1. Mock Interview 主流程已落地

`mock_interview` 已接入 Capability 体系，可跑完整模拟面试链路：
- 开始面试
- 提交作答
- 追问
- 评分
- 复盘
- 面试后画像写入

### 2. 面试记忆服务已建立

`deeptutor/services/interview/` 已实现按 `user_id` 隔离的记忆存储，包含：
- learner profile
- 历史 interview session
- active session 持久化与恢复

### 3. 面试协调器与子 Agent 已具备

`deeptutor/agents/interview/` 已有：
- 状态机协调器
- 追问 Agent
- 评分 Agent
- 复盘 Agent
- 画像写入器
- 上下文构造器

### 4. 资料入库脚本可用

`scripts/ingest_interview_data.py` 已能：
- 扫描 `input/` 面试资料
- 复制 raw 文件
- 生成 `interview_bank` manifest
- 在 embedding 不可用时跳过向量索引初始化

### 5. CLI 面试命令已补齐

`deeptutor interview` 已可用，包含：
- `start`
- `answer`
- `profile`
- `cancel`

这些命令复用 `mock_interview` capability，没有再造一套业务逻辑。

### 6. Embedding 健康检查已补齐

已新增 embedding health check：
- 可诊断当前 embedding provider 是否可用
- 可明确指出 `/embeddings` 是否可访问
- 入库脚本会先检查 health，再决定是否初始化 RAG 索引

### 7. RAG 已有 fallback

在向量索引不可用时，RAG 会退回到 manifest 元数据检索，避免知识库完全失效。

## 二、当前主要问题

### 1. 部分资料仍未完成内容级解析

当前 `interview_bank` 已经建立真实向量索引，但资料解析仍有缺口。

现状是：
- PDF 中有部分文件抽取为空或存在加密/关闭异常

- 已可解析资料已经进入向量索引

评分链路已经补了重试和非零兜底，但 live 模型下的长期稳定性还需要继续验证。

### 3. 画像质量还偏工程化

当前画像能写入，但更偏记录型，距离“稳定指导训练”的产品形态还有差距。

### 4. Live 评分稳定性验证

第一次执行：

```bash

```

结果：

```text
1 failed, 3 passed
```

发现问题：

模型有时会把 `total_score` 输出为 0-10 均分，而不是 0-80 总分。原代码优先信任模型返回的 `total_score`，导致好答案可能被记为 `7.0/80`，差答案被记为 `29.0/80`，出现排序反转。

已修复：

- `deeptutor/agents/interview/scoring_agent.py` 改为以各维度分数求和作为总分。
- 模型返回的 `total_score` 不再覆盖维度求和结果。
- 新增测试覆盖 `total_score` 为均分时仍按维度求和。

第二次执行 live 测试时，模型调用连续超时，底层 LLM factory 重试 9 次后失败：

```text
1 failed, 3 passed
openai.APITimeoutError: Request timed out.
```

已修复：

- 评分 Agent 对 LLM 调用异常增加本地启发式兜底。
- 评分调用的底层重试收敛为 `max_retries=1`，避免单次评分因外部模型超时拖住过久。
- 新增测试覆盖 LLM 抛错时仍返回非零启发式评分。
