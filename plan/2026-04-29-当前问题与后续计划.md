# DeepTutor 当前问题与后续计划

更新时间：2026-04-29

## 一、当前项目状态

DeepTutor 当前已经完成从通用学习助手到 agent-native 架构的主体改造，具备 CLI、WebSocket API、Python SDK 三类入口，并通过 Tool + Capability 两层插件模型承载 Chat、Deep Solve、Deep Question、Deep Research、Math Animator、Visualize、Mock Interview 等能力。

针对“公考 / 事业编面试 AI 教师平台”的 P0 建设，当前已经落地了以下关键能力：

- `mock_interview` 能力已接入 Capability 体系，支持开始面试、作答、追问、评分、复盘和画像回写。
- `deeptutor/services/interview/` 已建立按 `user_id` 隔离的面试记忆服务，支持 learner profile、历史面试 session 和 active session 持久化。
- `deeptutor/agents/interview/` 已建立模拟面试状态机、追问 Agent、评分 Agent、复盘 Agent、记忆写入器和上下文构造器。
- `scripts/ingest_interview_data.py` 已能扫描 `input/` 资料，生成 `interview_bank` 的 raw 文件与 manifest 清单。
- RAG 在向量索引不可用时已有 manifest 元数据检索兜底，避免知识库完全不可用。
- 面试相关测试已覆盖用户隔离、记忆读写、状态机、跨请求 active session 恢复和 RAG fallback。

整体判断：P0 主流程已经跑通，但仍属于“有条件可用”。当前最大短板不是没有框架，而是资料结构化、Embedding/RAG 闭环、真实模型稳定性、产品入口和评分校准还没有完全工程化。

## 二、当前主要问题

### 1. Embedding 与 RAG 向量检索未闭环

当前 DeepSeek 作为 LLM 可用，但不提供 embedding API，导致 `interview_bank` 的向量索引没有建立。系统目前依赖 manifest 元数据 fallback，只能按文件名、资料类型、题型、岗位等粗粒度信息召回资料。

影响：

- 抽题与资料引用不够精准，容易返回资料清单而不是真实题目内容。
- 评分和复盘暂时难以稳定引用老师方法论、高分作答和热点材料。
- 后续个性化训练推荐缺少可靠的知识依据。

### 2. `input/` 资料仍停留在清单化阶段

`input/` 中已有真题、高分作答、课程资料和方法论，但当前入库主要是文件级分类。高分录音、课程视频、PDF/PPTX 内部内容还没有完成统一转写、切分、标签校对和结构化建模。

影响：

- 平台知道“有哪些文件”，但还不能稳定知道“每个文件里有哪些真题、模板、失分点和示范表达”。
- 高分作答资料无法充分参与评分校准和示范生成。
- 老师方法论无法和题型、评分维度、常见扣分点建立稳定关联。

### 3. 模拟面试流程可用，但产品化入口仍需打磨

后端 `mock_interview` 能力已经具备文本版闭环，active session 也能跨请求恢复。但当前更偏底层 capability，实现还需要进一步进入 Web 工作台、CLI 命令和用户操作流程。

影响：

- 用户不一定能以自然、稳定的方式选择考试类型、岗位、题型和难度。
- 面试中断恢复、取消、重新开始、历史查看等体验还需要明确。
- 评分报告、追问、复盘、画像变化需要更直观地展示给用户。

### 4. 评分稳定性和追问质量仍需真实模型验收

当前已有评分 Agent、追问 Agent 和复盘 Agent，但 live LLM 测试默认跳过，真实模型下的稳定性还没有形成验收结论。已有报告也指出 `deepseek-v4-flash` 在追问判断时可能输出推理过程，且判断偏保守。

影响：

- 同一答案多次评分可能存在波动。
- 追问可能过少、过泛，不能稳定暴露薄弱项。
- 复盘报告可能出现建议泛化、证据不足的问题。

### 5. learner profile 已有雏形，但画像质量规则还较粗

当前画像分为 stable 与 dynamic，并能写入弱题型、低分维度、扣分原因和训练建议。但画像更新规则仍较简单，例如低分维度聚合、趋势判断、反复出现问题识别、单次偶然问题过滤等还不够细。

影响：

- 单场表现可能过度影响长期画像。
- 趋势分析目前只是占位式判断，不能支撑阶段性成长报告。
- 下一场训练的个性化建议仍偏粗粒度。

### 6. 多用户平台经验尚未开始沉淀

当前已经实现用户隔离，这是正确的 P0 前提。但平台级经验，例如常见失分模式、题型难度校准、追问策略效果、方法论提分效果，还没有匿名化聚合机制。

影响：

- 平台暂时只能记住单个用户，不能从多用户训练中系统性变聪明。
- 难以持续优化评分 rubrics、训练推荐和题库难度。
- 后续 P1/P2 需要补充隐私保护、聚合统计和平台经验写入规则。

### 7. 代码层还有若干短期清理项

从当前代码看，有一些不影响主流程但应尽快清理的工程问题：

- `followup_agent.py` 中存在不可达 `return`，追问判断解析逻辑需要收敛。
- `mock_interview.py` 的 `profile` 模式输出逻辑较临时，需要改成明确的 JSON/文本响应策略。
- `StableProfile.from_dict()`、`DynamicProfile.from_dict()` 对 bool、list、str 字段的恢复逻辑不够严谨。
- `memory_writer.py` 对低分维度、扣分原因的去重和来源记录还比较弱。
- `context_builder.py` 已有多角色上下文构造函数，但主流程实际使用还不充分。

## 三、后续计划

### P0 收尾：让当前闭环真正稳定可验收

目标：把“有条件通过”推进到“稳定可用”。

优先事项：

1. 配置可用 embedding provider，例如 Ollama `nomic-embed-text`、OpenAI embedding 或其他 OpenAI-compatible embedding。
2. 重新运行 `scripts/ingest_interview_data.py`，为 `interview_bank` 建立真实向量索引。
3. 修复短期代码清理项，重点处理追问判断、profile 输出、画像反序列化和记忆写入去重。
4. 执行面试相关完整测试，并在真实模型环境下补跑 live scoring consistency。
5. 建立 5-10 条人工验收样例：覆盖综合分析、计划组织、应急应变、人际沟通、岗位匹配等题型。

验收标准：

- 系统能从 `interview_bank` 检索真实题目或方法论片段，而不是只返回 manifest 清单。
- 用户能完成完整文本模拟面试，评分、追问、复盘和画像回写稳定。
- 同一答案多次评分分差处于可接受范围。
- 下一场训练能读取上一场薄弱项，并在追问或复盘中体现。

### P1：资料结构化与面试产品化

目标：把资料从“文件清单”升级为“可训练、可评分、可复盘”的领域知识库，并让用户入口完整可用。

优先事项：

1. 建立结构化资料 schema：真题、题型、岗位、难度、评分维度、方法论、高分作答、失分点、热点材料。
2. 对 `input/` 资料进行内容级切分和人工可校对标注，优先处理真题、老师方法论和高分作答。
3. 对高分录音建立转写流程，抽取高分结构、亮点表达、案例素材和表达节奏。
4. 在 Web 工作台中补齐模拟面试入口，包括配置面板、面试进行态、追问态、评分态、复盘态和历史记录。
5. 在 CLI 中补齐 `deeptutor run mock_interview` 或专用 interview 命令的交互流程。
6. 将评分报告结构化，前端能够展示总分、分维度得分、扣分证据、改进建议和历史对比。

验收标准：

- 用户能通过 Web 完成一场清晰的模拟面试，而不需要理解底层 capability 参数。
- 系统能引用老师方法论和高分作答支撑复盘建议。
- 每场面试都有结构化历史记录，可查看、导出、复盘。

### P2：画像质量与训练推荐

目标：让 learner profile 从“记录结果”升级为“指导训练”。

优先事项：

1. 优化画像写入规则，区分单次问题、重复问题、明显改善和长期短板。
2. 增加按题型、评分维度、时间窗口的趋势统计。
3. 建立训练推荐策略：下一题型、下一难度、是否需要模板提示、是否需要高分示范、是否需要专项追问。
4. 增加阶段性复盘报告，例如最近 5 场、最近 10 场、某一题型专项复盘。
5. 为画像事实增加来源记录，保证每条长期结论都能追溯到具体 session 和评分证据。

验收标准：

- 多场训练后，系统能识别稳定薄弱项，而不是只复述最近一场。
- 用户能看到分数趋势、维度趋势和训练建议变化。
- 个性化追问和复盘能解释“为什么建议这样练”。

### P3：平台级经验与知识图谱

目标：在保护隐私的前提下，让平台从多用户训练中沉淀共性经验。

优先事项：

1. 建立匿名化聚合规则，只沉淀统计规律，不暴露单个用户原始作答和身份信息。
2. 统计不同题型的常见失分点、常见追问触发点和常见提分路径。
3. 建立题型、方法论、评分维度、失分点、高分表达、热点材料之间的关系。
4. 用平台经验反向校准 rubrics、追问策略和训练推荐。
5. 在数据量足够后，再考虑引入轻量知识图谱或图数据库，而不是过早复杂化。

验收标准：

- 平台能输出“某题型常见问题”和“有效训练建议”的聚合结论。
- 新用户训练也能受益于平台级经验，但不会看到其他用户隐私。
- 评分、追问和推荐策略能随平台数据积累逐步优化。

## 四、建议近期排期

- 配置 embedding 并重建 `interview_bank` 向量索引。
- 修复追问判断、profile 输出、画像反序列化等代码清理项。

### 第 4-5 周：Web/CLI 产品入口

- 在 Web 工作台补齐 mock interview 使用入口。
- 展示面试状态、追问、分维度评分、复盘报告和历史记录。
- CLI 补齐可交互面试流程，方便测试和批量验收。
- 明确 session 恢复、取消、重新开始和历史查看规则。

### 第 6 周以后：画像增强与平台经验

- 引入多场训练趋势分析。
- 建立训练推荐规则。
- 开始设计匿名化平台经验沉淀。
- 根据真实用户数据校准评分与追问策略。

## 五、优先级结论

当前最应该先做的不是新增更多 Agent，而是把现有闭环做实：

1. 先完成 embedding 和 RAG 向量索引。
2. 再把 `input/` 资料做成可引用的结构化知识。
3. 同步稳定 mock interview 的真实模型表现。
4. 然后完善 Web/CLI 用户入口。
5. 最后再做画像增强、平台经验和知识图谱。

只要 P0 收尾完成，DeepTutor 就能从“具备面试训练能力的框架”进入“可真实用于公考 / 事业编面试训练的产品雏形”。
