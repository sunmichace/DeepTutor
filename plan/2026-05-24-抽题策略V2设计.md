# DeepTutor 抽题策略 V2 设计

更新时间：2026-05-24
分支：main
前置：picker V1 live + 合成验证完成（11/11 分支齐证据，见 `plan/2026-05-24-picker-v1-validation.md`）

## 1. 为什么要做 V2

V1 跑通了"画像 → 抽题 → 作答 → 画像"闭环，所有 11 个分支都拿到真实持久化证据。但 live + 合成数据暴露了 4 个真问题：

| # | 问题 | 严重度 | 来源 |
|---|---|---|---|
| 1 | `avoid_question_types` 与 `focus_question_types` 可重叠（语义自相矛盾） | 中 | 合成 5 场观察 |
| 2 | `build_query_with_hints` 只用 `focus_dimensions[0]`，多焦点丢失 | 中 | live R3 观察 |
| 3 | 难度递进只看总分均值，不区分题型 | 低 | V1 设计简化项 |
| 4 | 软降权权重 -0.20 vs focus +0.15 + diff +0.10 = +0.25，软降权永远输给 focus | 低 | 合成数据数值检验 |

**V2 不重写 picker，只修这 4 处 + 加更细粒度的可观测信号**。不引入外部 reranker、不改 RAGService 签名、不动评测脚手架。

## 2. 范围边界

V2 **只**做：
- 修上面 4 个真问题
- `PickerHints` 增加 `_MAX_FOCUS_DIMS_IN_QUERY = 2` 类配置常量，以便 A/B 切
- audit 工具输出 hints 与 query 的 round-trip 偏差（"picker 派生 vs query 实际包含"）

V2 **不**做：
- 不引入 BGE-reranker / ColBERT 等外部重排
- 不做 embedding 级别的 profile 注入
- 不改追问链路（followup 仍然单轮）
- 不引入 LLM 级别的 picker prompt
- 不做用户级别的标签偏好（"我只想练社会现象"）—— 这是产品层，不是抽题层

## 3. 四个修改

### 3.1 `avoid_question_types` 减去 `recent_weak_types`

**当前 V1 行为**

```python
# resolve_picker_hints
avoid_question_types: list[str] = []
for item in dynamic.resolved_dimensions:
    for qt in item.get("question_types") or []:
        avoid_question_types.append(qt)
```

**问题**：合成 5 场跑出来的实际 hints：

```
focus_question_types:  ['计划组织', '社会现象', '综合分析']
avoid_question_types:  ['综合分析', '社会现象']
```

`'综合分析'` 和 `'社会现象'` **同时**在 focus 和 avoid 里，picker 一边强推一边降权，自相矛盾。

**根因**：`avoid` 的语义本应是"这些题型上你已经回暖了，可以避开换其他维度练"。但用户**当前**还在该题型上薄弱（recent_weak_types 包含），就不该 avoid。

**V2 方案**

```python
focus_qt_set = set(focus_question_types)
avoid_question_types = [
    qt
    for qt in (raw_resolved_qts)
    if qt and qt not in focus_qt_set
]
```

**取舍**：
- ✅ 消除矛盾，picker 输出语义自洽
- ✅ 不需要新数据结构
- ⚠️ 可能让 `avoid` 经常空——但这恰好反映"用户还没有完全回暖的题型"，是真实状态
- ❌ 不修 `_filter_and_rerank` 的 -0.20 权重（见 §3.4）

**验收**

新增 fixture `profile-picker-avoid-focus-disjoint`：
- sessions 同时让"综合分析"是 recent_weak（仍弱）+ "岗位匹配度"是 resolved 来自"综合分析"
- 期望 hints.focus_qt 包含"综合分析"
- 期望 hints.avoid_qt **不**包含"综合分析"（因被 focus 减掉）

### 3.2 query 用全部 focus_dimensions（最多 2 个）

**当前 V1 行为**

```python
if hints.focus_dimensions:
    extras.append(hints.focus_dimensions[0])  # 只用第一个
```

**问题**：live R3 实测：

```
focus_dimensions = ['论据与案例质量', '结构化表达']
query 实际包含 = '论据与案例质量'   ← 只第一个
```

第二个焦点维度"结构化表达"被丢弃，但它和"论据"在 R1+R2 都是 ≤5。

**V2 方案**

```python
_MAX_FOCUS_DIMS_IN_QUERY = 2

if hints.focus_dimensions:
    extras.append(" ".join(hints.focus_dimensions[:_MAX_FOCUS_DIMS_IN_QUERY]))
```

**取舍**：
- ✅ 多焦点维度都进 query，embedding 召回更精准
- ✅ 上限 2 防止 query 膨胀稀释主信号
- ⚠️ embedding 对单 token 比对长 query 敏感——但当前 query 已经被 active_suggestion（≤40 字）拼接过了，再加一个维度名（≤10 字）影响小
- 验证空间：A/B 跑同一用户 hits@5 对比

**验收**

- 单测：`build_query_with_hints` 在 `focus_dimensions = ['A','B','C']` 时 query 包含 A 和 B、不包含 C
- 单测：`focus_dimensions = ['A']` 时和 V1 行为一致
- live：选一个有 ≥2 个 focus_dim 的用户，对比 V1 和 V2 query 的 RAG `sources[:5]` 命中差异

### 3.3 难度递进按题型分组（v2.1，可推迟）

**当前 V1 行为**

```python
def _difficulty_from_recent_scores(recent_sessions, requested_difficulty):
    last_three = recent_sessions[:3]
    avg = sum(s.total_score for s in last_three) / 3.0
    if avg >= 70: return "hard"
    if avg <= 50: return "easy"
    return "medium"
```

**问题**：用户最近 3 场分别是「综合分析 30 / 综合分析 35 / 组织管理 80」均值 48 → easy；但用户**已经掌握组织管理**，下一场如果再抽组织管理应该 hard。

**V2 方案（按题型分组）**

```python
def _difficulty_for_question_type(recent_sessions, qt, requested):
    same_qt = [s for s in recent_sessions if s.question_type == qt][:3]
    if len(same_qt) < 2:
        return _difficulty_from_recent_scores(recent_sessions, requested)  # fallback to global
    avg = sum(s.total_score for s in same_qt) / len(same_qt)
    if avg >= 70: return "hard"
    if avg <= 50: return "easy"
    return "medium"
```

**取舍**：
- ✅ 难度更贴用户在该题型的实际水平
- ⚠️ 大多数用户在每个题型只有 1-2 场，会频繁回退到全局均值——增益有限
- ⚠️ 调用方目前只传 `question_type`，但实际 RAG 检索结果可能跨题型——意味着"按题型推断难度"和"实际抽到什么题型"对不上

**结论**：**V2.1，推迟。** 等真实用户每个题型积累到 ≥2 场再启用。当前 V2 不做。

### 3.4 软降权权重校准

**当前 V1 数学**

```
focus_qt 命中:        +0.15
target_difficulty:    +0.10
avoid_qt 命中:        -0.20
原始 RAG score:        ~0.6 ~ 0.8
```

**最坏 case**：source A `qt 在 focus` + `diff 匹配` 加 +0.25；source B `qt 在 avoid` 减 -0.20。两者原 score 相同时，差距 0.45——A 完胜。

**问题**：avoid 的实际效果**永远输给** focus + diff_match 组合。如果 §3.1 已经让 avoid/focus 不重叠了，那 avoid 又只针对 resolved 的题型，本来就该是"软降权"语义。

**V2 方案**

不动权重。`-0.20` 在 §3.1 修复后已经是合理软降权——重叠问题修了，权重就够用。

**留给 V2.x 的 telemetry 事件**：在 `_filter_and_rerank` 末尾日志输出实际 bonus 分布，等真实数据足够多时再看是否需要调权。

```python
logger.debug(
    "rerank_telemetry hits=%d focus_match=%d diff_match=%d avoid_hit=%d",
    len(enriched), n_focus, n_diff, n_avoid,
)
```

## 10. 风险与回滚

- 风险 1：V2 query 加多个焦点维度后召回反而下降（embedding 被稀释）
  - 缓解：A/B 对比，保留 `_MAX_FOCUS_DIMS_IN_QUERY` 常量便于回切到 1
- 风险 2：avoid 减 focus 后 avoid 经常空，数据稀疏
  - 缓解：这是正确语义，audit 工具能看到 avoid 的实际命中率，便于产品判断要不要扩大 avoid 触发条件
- 回滚：每条修改单独 commit，PR 拆 4 个 sub-PR 或在同一 PR 内 squash
